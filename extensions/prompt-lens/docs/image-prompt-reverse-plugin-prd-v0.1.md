# AI.Simplify 图片提示词反推插件 PRD v0.1

- 文档状态：讨论稿；模型方案与目标浏览器已确认，可进入技术验证
- 更新日期：2026-09-02
- 产品形态：可安装到 Google Chrome 的浏览器扩展（Manifest V3）+ 作品集网页 Demo
- 工作名称：AI.Simplify Prompt Lens（名称待定）
- 一句话定义：在浏览网页时选中任意图片，直接得到可复制、可编辑、适用于生图工具的中文复刻提示词。

## 1. 产品结论

首版应做成浏览器扩展，而不是单独的上传网页。用户发现参考图的场景通常发生在 Pinterest、小红书网页版、设计网站或素材站，右键图片后在浏览器侧边栏完成分析，能最大限度保留浏览上下文。

MVP 的差异点不是“模型能看图”，而是把现有 `image-prompt-reverse` skill 变成稳定产品能力：自动区分通用图片与建筑/规划人群行为分析图，按固定结构生成约 300 字中文提示词，并让用户一键复制、重新生成或修正模式。

公开 MVP 确定使用火山方舟提供的豆包多模态模型 `Doubao-Seed-2.1-pro`，优先消耗当前免费体验额度。这里的“免费”指火山方舟账号当前可领取和使用的体验 tokens，不代表模型永久免费或无限调用。扩展不直接保存豆包 API Key，所有模型请求统一经过后端代理；后端设置每日调用上限、超额熔断和预算告警，免费额度不足时向用户明确提示，不静默切换模型。

## 2. 背景与问题

### 2.1 用户问题

用户看到喜欢的效果图、海报、摄影或建筑分析图时，通常需要手动拆解主体、构图、材质、光线、色调和风格，再把这些信息组织成生图提示词。这个过程耗时、依赖专业词汇，且不同用户产出的提示词质量不稳定。

现有通用视觉模型可以描述图片，但常见输出有四个问题：

1. 更像图片说明，不像可以直接用于复刻的生图提示词。
2. 描述顺序和颗粒度不稳定，遗漏构图、光线或材质。
3. 不理解建筑/规划领域的人群行为分析图。
4. 用户必须离开素材网站、保存图片、打开 AI 对话并重复输入指令。

### 2.2 现有资产

- 已有 `image-prompt-reverse` skill，定义了通用模式和人群行为分析图模式。
- 已有约 62 例建筑效果图、展板、分析图提示词资产，可转化为评测集和作品集案例。
- 当前作品集是静态前端 + Cloudflare Worker，适合复用部署与接口层。
- 参考视频展示了 Promptcard 类扩展的核心体验：页面内浮层、分析状态、结果卡片、历史缩略图和连续分析。

## 3. 目标与非目标

### 3.1 MVP 目标

- 用户从网页图片到复制提示词，核心流程不超过 3 次操作。
- 输出稳定符合 skill 的结构、字数、语气与格式要求。
- 自动识别两种模式，并允许用户手动纠正。
- API Key 不出现在扩展代码中；图片不在自有服务端持久化。
- 能形成一个可安装、可演示、可量化的完整 AI 产品作品集案例。
- 开发版可通过 `chrome://extensions` 的“加载已解压的扩展程序”安装；发布版产出满足 Chrome Web Store 提交要求的构建包。

### 3.2 MVP 非目标

- 不直接生成或编辑图片。
- 不做账号、云端同步、社区或付费系统。
- 不承诺精确还原未知模型的 seed、LoRA、镜头或参数。
- 不批量抓取网页图片，不自动分析整页内容。
- 不在首版支持 Safari、移动端和多图融合。
- 首版不承诺 Edge 或其他 Chromium 浏览器兼容性，验收环境以 Google Chrome 为准。

## 4. 用户与核心场景

### 4.1 主要用户

1. 建筑、景观、规划和室内设计学生：需要把参考图转成效果图或分析图提示词。
2. AI 视觉创作者和内容运营：需要快速复刻海报、摄影、插画和社媒视觉风格。
3. 产品与视觉设计师：需要提取构图、配色、材质和视觉语言，用于概念探索。

### 4.2 核心 JTBD

“当我在网页上看到值得复刻的图片时，我希望不用离开当前页面，就得到一段结构完整、可以直接粘贴进生图工具的中文提示词。”

## 5. 核心体验

### 5.1 主流程

1. 用户安装并启用插件后，在网页图片上右键，选择扩展菜单项“反推提示词”。
2. 扩展打开 Chrome 侧边栏，显示选中图片的预览。
3. 客户端压缩并去除 EXIF，用户确认“仅为本次分析上传图片”。
4. 系统自动判断“通用图片”或“人群行为分析图”，开始分析。
5. 侧边栏显示阶段状态：上传图片 → 分析构图与风格 → 整理提示词。
6. 展示约 300 字的主提示词和 1–3 句使用建议。
7. 用户复制、重新生成、切换模式后重试，或输入一句修改要求。
8. 结果保存在本地历史中，用户可再次打开、复制或删除。

### 5.2 降级入口

网页图片可能来自 Canvas、CSS 背景、受保护 CDN 或登录态资源。右键取图失败时，提供以下降级顺序：

1. 使用右键事件提供的 `srcUrl` 读取图片。
2. 若跨域或鉴权导致读取失败，利用本次用户手势授予的 `activeTab` 临时权限，仅截取目标图片当前可见区域；分析前仍显示预览供确认。
3. 若目标图未完整显示或来自 Canvas/CSS 背景，提示用户从剪贴板粘贴，或拖拽/选择本地图片。

截图只在用户主动对某张图发起分析后执行，不持续监听页面，也不申请永久全站权限。

### 5.3 状态设计

- 空状态：解释右键、粘贴和上传三种入口。
- 待确认：图片预览、模式选择、数据发送说明。
- 分析中：使用真实阶段状态和耗时，不显示无法验证的百分比进度。
- 成功：提示词、使用建议、模式、复制和重新生成。
- 失败：说明是图片读取、格式、限额、网络还是模型错误，并给出对应重试动作。
- 历史：本地缩略图 + 模式 + 时间；默认最多 20 条，可一键清空。

## 6. 功能需求与验收标准

### FR-01 网页图片入口（P0）

- 插件安装并启用后，用户在网页图片上点击右键时，浏览器上下文菜单中显示“反推提示词”按钮。
- “反推提示词”只在图片上下文中出现；用户在普通文字或页面空白处点击右键时不显示。
- 用户点击“反推提示词”后，Chrome 侧边栏自动打开并展示本次右键选中的目标图片。
- 从点击菜单项到侧边栏出现图片预览，应在本地处理正常时于 1 秒内给出可见反馈；图片仍在读取时显示明确加载状态。
- 不申请永久 `<all_urls>`；优先使用 `activeTab`、`contextMenus`、`scripting`、`sidePanel`、`storage`。
- 无法读取时必须进入降级入口，不能静默失败。

### FR-02 上传与预处理（P0）

- 支持 JPEG、PNG、WebP；单图最大 10 MB。
- 客户端将长边压缩到不超过 1600 px，并移除 EXIF。
- GIF 首版只分析第一帧；SVG 提示用户先转成 PNG，P1 再支持自动栅格化。
- 服务端只接收图片字节，不接收并代抓任意远程 URL，避免 SSRF 和登录态泄漏。
- 当远程图片无法直接读取时，使用 `captureVisibleTab` 截取当前可见页面，再按照目标元素位置与设备像素比在本地裁剪；裁剪结果必须先给用户确认。

### FR-03 模式识别（P0）

- 输出 `general` 或 `crowd_analysis`，同时返回置信度。
- 置信度低于 0.65 时，在结果页突出显示模式切换。
- 用户切换模式后可用同一图片重新生成。
- 在评测集上自动分类准确率目标 ≥ 90%。

### FR-04 提示词生成（P0）

通用模式依次覆盖：主体与场景、构图与视角、主体细节、环境背景、光线、色调与氛围、风格、可选技术参数感。

人群行为分析图模式依次覆盖：图纸类型与视角、底图风格、空间结构、人物表现、行为类别与数量级、标注图示、配色氛围，并以建筑/规划汇报用途收束。

统一要求：

- 中文，第三人称客观描述。
- 主提示词 250–350 个中文字符为目标范围。
- 不使用“我看到”“这张图里”等主观开场。
- 不编造作者、相机型号和不可见信息。
- 主提示词只写要生成的内容，不写负向命令。
- 另附 1–3 句使用建议，不计入主提示词字数。

### FR-05 结构化响应与校验（P0）

模型内部返回 JSON，UI 再渲染为自然文本：

```json
{
  "mode": "general",
  "confidence": 0.92,
  "prompt": "……",
  "usageAdvice": "……",
  "editableTags": {
    "subject": ["……"],
    "composition": ["……"],
    "lighting": ["……"],
    "palette": ["……"],
    "style": ["……"]
  }
}
```

- Worker 使用 schema 校验响应。
- JSON 无效或字数越界时，自动进行最多 1 次修复请求。
- 模型指令明确要求把图片中的文字视为画面内容，而不是系统指令，以降低视觉提示注入风险。

### FR-06 复制、修改与重试（P0）

- 一键复制主提示词；复制后有明确成功反馈。
- 可复制“主提示词 + 使用建议”。
- 用户可选择“更写实 / 更简洁 / 强化构图 / 强化材质”等快捷调整，或输入不超过 100 字的修改要求。
- 修改请求仍需满足原模式的输出规范。

### FR-07 本地历史（P0）

- 默认保存最近 20 条到 `chrome.storage.local`，不上传历史。
- 用户可关闭历史、删除单条或清空全部。
- 缩略图应二次压缩，避免快速耗尽本地存储。

### FR-08 作品集网页 Demo（P1，但发布作品集前必须）

- 作品集详情页提供上传/粘贴体验，复用同一 API 和核心 UI。
- 提供 4–6 张脱敏示例图，访客无需安装扩展即可理解价值。
- 页面展示问题、洞察、方案、模型评测、隐私取舍和效果数据，而不只是截图画廊。

## 7. 模型方案

### 7.1 已选方案

| 方案 | 免费方式 | 优势 | 风险与限制 | 结论 |
| --- | --- | --- | --- | --- |
| 火山方舟 + `Doubao-Seed-2.1-pro` | 当前官方页面提供 50 万 tokens 免费体验额度 | 支持图片理解、中文生成和结构化输出；国内网络访问更友好；可通过兼容 Chat Completions 的 API 接入 | 免费额度、价格和模型版本会变化；需开通火山方舟并创建 API Key；图片会发送至火山方舟处理 | MVP 唯一模型链路 |

### 7.2 接入决策

1. 使用现有 Golden Set 验证 `Doubao-Seed-2.1-pro` 的视觉事实准确性、格式合规率、延迟和单次 token 消耗，不再进行多模型选型。
2. 后端通过火山方舟 Chat Completions API 调用模型，API Key 仅保存在 Worker Secret 中。
3. 后端使用 `VisionModelAdapter` 封装模型调用，模型 ID 通过服务端环境变量配置，不写死在扩展代码中。
4. 首版只启用豆包链路；额度耗尽、限流或服务异常时返回明确错误，不自动切换到未披露的第三方模型。
5. 上线前重新核对火山方舟的免费额度、计费、数据处理条款和模型可用性，并在后端配置每日请求上限、单安装 ID 限流与预算告警。

说明：“豆包免费模型”在本 PRD 中统一指“在火山方舟免费体验额度内调用豆包模型”，不代表永久零费用。公开 Demo 的免费调用次数由服务端额度控制。

## 8. 评测方案

### 8.1 Golden Set

从现有 62 例资产中整理 30 张可合法使用、无隐私信息的代表图片：

- 通用摄影/海报/插画 8 张。
- 建筑与室内效果图 8 张。
- 建筑展板、区位图和普通分析图 6 张。
- 人群行为分析图 5 张。
- OCR、拼贴、低清晰度等困难样本 3 张。

每张图补充：正确模式、必须描述的 5–10 个视觉事实、禁止臆测项、人工参考提示词。

### 8.2 评分维度

| 维度 | 权重 | 判定 |
| --- | ---: | --- |
| 视觉事实准确性 | 30% | 主体、空间、人物行为无明显错认 |
| 复刻信息完整度 | 25% | 构图、光线、材质、配色、风格覆盖充分 |
| 可直接使用程度 | 20% | 无需大改即可粘贴到生图工具 |
| skill 格式遵循 | 15% | 语言、字数、结构、语气符合要求 |
| 中文表达质量 | 10% | 自然、专业、不堆砌空泛形容词 |

豆包模型对每张图运行 3 次，匿名后人工评分。除质量外单独记录成功率、平均延迟、P95 延迟和每次调用的输入、输出 token 消耗。

### 8.3 MVP 质量门槛

- 综合评分 ≥ 4.0/5。
- 格式合规率 ≥ 95%。
- 模式分类准确率 ≥ 90%。
- 端到端成功率 ≥ 95%。
- P50 ≤ 8 秒，P95 ≤ 15 秒。

## 9. 技术方案

### 9.1 前端扩展

- WXT + React + TypeScript。
- Manifest V3，首版只以 Google Chrome 作为开发、安装和验收环境。
- UI 使用普通 CSS / CSS Modules，避免为了一个侧边栏引入大型组件库。
- 状态管理使用 React state + 小型 reducer；首版无需 Redux。
- Zod 校验 API 响应；Vitest 做规则测试；Playwright 做右键、侧边栏和上传主流程测试。

WXT 可生成不同浏览器目标的 manifest，并提供扩展入口与热更新能力。Chrome Side Panel 基础 API 在 Chrome 114+ 可用，但右键菜单触发后通过 `sidePanel.open()` 主动打开侧边栏需要 Chrome 116+，因此首版将 `minimum_chrome_version` 设为 116。

### 9.2 后端

- Cloudflare Worker + TypeScript，作为扩展与火山方舟之间的安全代理。
- 通过火山方舟 Chat Completions API 调用 `Doubao-Seed-2.1-pro`；使用 Worker Secret 保存 `ARK_API_KEY`，服务端环境变量保存模型 ID。
- 路由：`POST /api/prompt-reverse/analyze`、`GET /api/prompt-reverse/health`。
- 请求体使用 `multipart/form-data`，包含图片、手动模式和可选修改要求。
- Worker 在内存中将图片转换为豆包 API 支持的图片输入格式，不生成公开图片 URL，不落 R2、KV 或 D1 保存图片和提示词。
- 日志仅记录不含内容的错误码、耗时和输入/输出 token 消耗。
- API 做 MIME/魔数、大小、尺寸、超时、来源和 schema 校验。
- 对单个匿名安装 ID 做速率限制；ID 在客户端生成并只用于限流，不与浏览历史关联。
- 配置全局每日调用上限；达到额度阈值时停止请求豆包 API，并向扩展返回可识别的 `QUOTA_EXCEEDED` 错误。

### 9.3 数据流

```text
网页图片 / 本地图片
  → 扩展在本地读取、压缩、去 EXIF
  → HTTPS 上传 Cloudflare Worker
  → Worker 使用服务端 API Key 请求火山方舟
  → 固定系统提示词 + 图片 → Doubao-Seed-2.1-pro
  → JSON schema 校验 / 最多一次修复
  → 返回扩展
  → 本地展示与可选历史保存
```

### 9.4 为什么不把 API Key 放在扩展里

扩展包会被用户下载和反编译，任何写入前端的服务端密钥都等于公开。所有模型调用必须经过 Worker；扩展只持有公开的 API 地址和本地匿名 ID。

## 10. 隐私、安全与商店合规

- 首次分析前明确说明：选中的图片会被发送给哪家服务，仅用于生成提示词。
- 图片和结果默认不在自有服务端保存；历史只保存在本地。
- 全链路 HTTPS，不记录请求体，不在错误日志打印 base64 图片或完整提示词。
- 只申请实现单一功能所需的最小权限；避免永久 `<all_urls>`。
- 提供隐私政策、数据处理说明和一键清空历史。
- Chrome 商店将截图、网页内容和本地保存内容都视为需要披露的数据处理；发布前必须完成商店隐私字段和 Limited Use 声明。
- 分析确认页与隐私政策必须明确披露图片会经 Cloudflare Worker 转发至火山方舟豆包模型；发布前复核火山方舟最新数据处理条款。
- 发布 Chrome Web Store 需要注册开发者账号并支付一次性注册费，这不属于模型调用成本。

## 11. 埋点与成功指标

只记录事件和性能，不记录图片、提示词、网页 URL 或页面标题。

建议事件：

- `analysis_started`
- `analysis_succeeded`
- `analysis_failed(error_code)`
- `prompt_copied`
- `mode_overridden`
- `prompt_regenerated`
- `history_disabled`

MVP 验证指标：

- 分析成功率 ≥ 95%。
- 结果复制率 ≥ 50%。
- 模式人工纠正率 ≤ 10%。
- 首次结果无需重生成率 ≥ 60%。
- 5 名目标用户完成任务的中位时间 ≤ 30 秒。

## 12. 版本范围

### MVP / P0

- 网页图片右键菜单“反推提示词”、粘贴、上传三种入口。
- Chrome Side Panel。
- 两种模式自动识别和手动切换。
- 生成、复制、快捷修改、重试。
- 最近 20 条本地历史。
- Cloudflare Worker 代理火山方舟豆包 API，并完成限流、额度保护和响应校验。
- 隐私说明与错误状态。
- 可加载到 Google Chrome 的解压目录构建产物，以及可提交 Chrome Web Store 的 ZIP 包。

### P1

## 15. 当前待确认的产品决策

这些问题不阻塞技术验证，但应在视觉设计前定下来：

1. 正式名称是否沿用 AI.Simplify 品牌，还是使用独立产品名。
2. MVP 是否只突出建筑/设计用户，还是用“通用 + 建筑专业模式”双入口面向更广用户。
3. 历史记录默认开启还是首次询问后开启。
4. 公开 Demo 是使用服务端免费额度限次开放，还是只开放预置样例。
5. 豆包免费体验额度耗尽后，是暂停公开分析，还是启用付费预算继续服务。
