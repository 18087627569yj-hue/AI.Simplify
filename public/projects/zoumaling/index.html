01 / CONTEXT

规划不应该只停在一张完成图里

乡村项目从规划到落地往往周期很长。传统成果能描述空间，却很难提前回答：游客会被什么吸引、愿意怎么走、在哪停留，以及哪些建设内容真正值得优先投入。

因此，我把“预运营”设为项目核心：用数字体验提前组织村庄内容、模拟完整游程，并通过行为记录形成规划与运营之间的反馈回路。

02 / THE PROBLEM

三个断点，让规划、体验与运营彼此脱节

01

游客看不懂

规划图信息完整，但缺少可进入的故事和清晰的游览线索。

02

运营难验证

路线与业态主要依赖经验判断，建设前缺少真实偏好反馈。

03

内容难更新

展示端与管理端分离，景点、路线与建设策略难以持续维护。

03 / EXPERIENCE STRATEGY

先给游客一个身份，再给他一条有理由的路线

系统没有从功能菜单开始，而是先通过简短测试识别体验倾向，生成角色、推荐点位和游览理由。游客不是在浏览数据库，而是在领取一段属于自己的走马岭旅程。

  • 身份测试作为入口降低理解门槛，让村庄文化以角色和任务被感知。
  • 地图成为体验主场路线、点位、故事与服务信息在同一空间关系中展开。
  • 推荐结果可解释每个点位都对应游客偏好，而不是一条无法理解的固定路线。

04 / SYSTEM DESIGN

一套系统，同时服务游客与运营者

游客端负责把规划讲成旅程，管理端则把旅程拆回可编辑的数据。景点、路线、前期建设和用户行为彼此关联，运营者能持续更新内容，并观察不同决策如何影响体验。

游客偏好测试与选择
→
个性路线点位与故事
→
行为数据点击与停留
→
运营迭代内容与建设

05 / OPERATIONS LOOP

让每一次点击，都成为下一轮规划的线索

后台记录路线生成、点位访问、点击与停留等事件，并以点位热度、常见路线组合和事件趋势呈现。它不替代规划判断，而是为建设优先级和内容调整增加一层可观察依据。

06 / REFLECTION

从“展示规划”走向“提前运营”

这个项目验证了一个更主动的乡村数字化路径：网页不只是成果汇报的外壳，它可以成为内容试验场、游客体验入口和规划反馈工具。

下一阶段将继续补充真实用户测试，校准身份题目与路线推荐逻辑，并把数据反馈进一步映射到业态、活动和建设时序中。
